# ZIPちゃん：①記憶断片想起・②逐文操作選択 試作

2026-10-27。**③Surface生成を実装していない**構造検査。外部API・LLM・GPUは使用しない。選択器はPython標準ライブラリのみ。

## データ

- `inputs/human_107.csv`：先に作成した人間原文の改行単位107行と分析用発話機能。話題はH04(23行)・H06(42行)・H07(42行)。
- `inputs/human_highlights.html`：以前の原文青/黄/黄緑文字単位ハイライト。
- `prepare.py`：原文の内容・出典から、**人手解釈を含む**75個の記憶断片（F=事実、E=本人の反応、T=本人の考え）と106本の関係リンクを作る。明示的な根拠がある主観的疑念や仮定は、確定した事実へ昇格させない。
- `memory.json`：知識断片と型付きリンク。`source_lines`は監査用で、`engine.py`の選択スコアには使わない。`requires`は数量計算や訂正の論理的前提条件。リンクは先行研究等から自動抽出したものではなく、**同じ人間原文から設計者が逆算したもの**であり、話の順序を間接的に含んでいる可能性がある。
- `human_reference.json`：人間原文1行内で最も文字数の多い色を、比較指標のために分類したファイル。**`engine.py`は読み込まない**。

## 制御器

`engine.py` は現在の話題、最後の根拠、直近の操作、提示済み根拠、評価の活性、逸脱先からの復帰スタックを保持する。候補は現在のMemory内の未使用断片および直接リンクのある別Memory断片。1断片を選ぶたびに、`REPORT/REACT/APPRAISE/COMPARE/REAPPRAISE/SPECULATE/REPAIR/ASSOCIATE_SHIFT/RESUME`などの操作と証拠IDを出力する。**自然言語の新規発話は作らない。**

`--mode graph` は根拠の有無・意味リンク・重要度中心。`--mode state` は上記に色の連続抑制、短期評価、意味のある再訪を足す（A/Bテスト）。`--cross`で関係リンクから別エピソードへ一時移動し、根拠が残れば元へ戻す。

## 再実行

Python 3.11以上、データ再作成には `beautifulsoup4` のみ必要。

```bash
pip install beautifulsoup4  # prepare.py のみ
python prepare.py
python engine.py --seed 17 --mode graph > example_trace.json
python engine.py --seed 17 --mode state --cross > example_cross_trace.json
python evaluate.py
```

検証成果物：`report.html`（全文表とストライプ）、`engine_trace.csv`（全操作と出典）、`metrics.json`（全seed統計） 。

## 検査対象・結論

人間（23/42/42行）と、機械が選ぶ発話**操作（18〜32回）**の主色列について、切替率、色比率、最長同色連続長を比較する。40seed ×3話題×2方式。さらに、機械側の色の内訳を固定して並びだけシャッフルした2000回の対照を用意する。

結果：**既存Memoryを細分化し、型付きリンクを探索するだけで青・黄・黄緑のまだらな操作列は作れる**。ただし「状態の反復抑制を追加すれば人間に近づく」という仮説は支持されず、射的ではむしろ切替過剰。グラフのみ・状態ありのいずれも、ランダム並べ替えより明確に良いとは一貫して言えない。さらに、情報の提示順が意味的にぎこちない部分がある。

この研究は同じ原文を使って手作業でグラフ化・評価している**in-sample機構試験**。未知人物・未知話題への汎化なし。人間の改行とMemory断片は同粒度でない。評価はストライプの外観であり、出来事の連続性・実際の発話品質・新しい考えの自発的生成の検証ではない。

## 既知の改善点

- カラー比率と遷移形を合わせるための明示的ペナルティは強すぎる場合がある。むしろ根拠リンクの質・適切なタイミングを優先すべき。
- このグラフのリンクが人間原文の展開情報を符号化しているため、未知の原文からのMemory自動構築方法は未解決。
- 脱線・復帰は動いたが、復帰時に何を語るべきかは粗い。
- ①②だけなので出力の色は**予定された発話機能**を示す。③が実際にその機能を表現するかは未測定。
