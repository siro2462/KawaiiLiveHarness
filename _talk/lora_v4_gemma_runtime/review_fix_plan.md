# v5 ZIPレビュー対応 — 限定修正計画

2026-10-15。修正前の8ソースとCPU再現結果を `audit/review_20261015/` に保全した。

## 修正する範囲

1. 元Memoryの保存先と今回の選択を分離する。空の検索候補は選択なし。期限内active Planの継続と、新しい検索が空だった場合を区別する。
2. 現行の1件制約を維持し、Plan検査・実Talk入力・Talk検査の根拠ID/本文hashを完全一致させる。過去Memoryは監査用に残しても検査根拠へ暗黙追加しない。
3. 生成例外を入力長・JSON制約・モデル実行失敗に分類。回復可能なものだけ最大1retry、OOM/デバイス障害は追加GPU呼出せず終了。未知の実装例外はログ保全して再送出する。根拠本文を削って入力長を解決しない。
4. 省略された過去の感覚経験と明示的日時追加の既知失敗を限定的に修正し、拒否/許容の固定CPU評価セットで検出漏れ・誤検出を別集計する。未検出を安全/正しいとは表示しない。
5. フェイクPlanner/Talkと実SQLiteによるCPU結合検査を追加する。Memory切替/検索なし/Plan期限/最大retry/根拠一致/候補破棄/部分再生/永続化/実装例外を確認する。
6. αの外部提案は1Memoryに制限する。αの内部検索・自発起動は今回実装しない。

モデル・LoRA・元Memory・旧結果・sampling・検索/反復閾値を変更しない。新LLM検証器・新会話進捗DB・台本生成は追加しない。

## 評価の区別

- JSON形式成功、Memory選択(use_memory/ID)、実際にTalkへ渡した根拠、CPU検出率、実発話の正確性・自然さを別に扱う。
- 保存済み形式probeの4/4 valid・4/4 use_memory=falseはそのまま保持し、新RuntimeのMemory選択成功と読み替えない。
- 同義反復/話題進展はログと全文目視で判定。直近5Planの観測ログは制御命令にしない。
- CPU結合と2700字/4.5字秒の模擬再生は実TTS/配信ではない。実TTSのack・割込み・再起動接続は未検証として残す。
- CPU合格後に短いGemma接続診断→固定36→連続発話を行う。モデル品質のための同条件再実行はしない。
