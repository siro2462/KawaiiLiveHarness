# v5 Memory事実検査の反例・許容例

次の改修で使う検査計画。**事実検査器はまだ実装完了ではない。** 例はCPUテストの文章で、モデルの新しい出力として扱わない。

元Memory S2B: 「カレーを作った。炊飯器のスイッチを押し忘れていて、ご飯がなかった。冷凍していたうどんにかけて食べた。」

| 候補表現 | 扱い | 検査する点 |
|---|---|---|
| 冷凍していたうどんにカレーをかけて食べた | 許容 | 元Memoryの内容 |
| 冷凍していたうなぎの蒲焼きをカレーにかけて食べた | 不採用 | 対象の追加・入替。use_memory=falseでも具体経験の根拠検査を省略しない |
| うなぎとカレーって合うのかな？ | 許容 | 一般的な連想・質問。実際に食べた経験には変えない |
| 合うのかなと思って、うなぎをカレーにかけて食べてみた | 不採用 | 質問を含んでも、後半は実体験の断定。文全体を疑問扱いで免除しない |
| 今カレーを作っているところ | 不採用 | 過去→現在進行の改変 |
| カレー作るのって、意外と手がかかるよね | 許容 | 一般的感想。物語の時間軸を変えていない |
| ご飯はちゃんと炊けていた | 不採用 | 有無・否定の反転 |
| 甘めだったかな？ | 許容 | 主観的な感想。味の確定情報がないことだけで拒否しない |
| この前は三人にカレーを作ってあげた | 不採用 | 人数と経験の無根拠な追加 |
| うどんが炊飯器にあったからスイッチを押し忘れた | 不採用 | 位置・因果の新しい断定 |

S3Bの「同じ看板の写真を十枚消した」に対する、Talkの実出力「1万2016枚。えっ？」は保存済みの別の反例。十枚を消した話と総写真枚数を区別し、「削除枚数を12016枚に変更した」と自動断定しない。根拠のない数値を出したことを検査対象にする。

## 実装・評価の原則

- 元Memoryを読み取り、Plan/Recent/自己生成文を元Memoryの事実へ昇格させない。
- 物・行為・時点・否定・因果の照合と、HTML/形式/反復を別の結果にする。
- 初期実装の対象範囲と未検証範囲を明記する。狭い字句検査の「問題検出なし」を事実性の証明にしない。
- 曖昧な時制、冗談、見立て、主観的感想を一律拒否しない。許容例の退行も確認する。
- 事実検査で拒否したPlanはpending/last_validに入れない。拒否した発話はEvent Storeの再生確定履歴へ入れない。
- 最大2attemptを保ち、再生成や空再生が増えていないか、全文と一緒に記録する。
- 新LLM検証器・再学習を、この段階に追加しない。
